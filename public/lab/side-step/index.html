Ten ideas that live in both lanes

In six of them the CS note came first. In the other four the AI version came first, and its classical form showed up months later on the CS side. Four of the ten were completed in September 2026.

Each strut joins the dates of a pair's two notes, CS on top and AI below. Select one to jump to it.

01

A dictionary that blurs

completed 11 Feb 2026

query · key · value122 days

Attention takes its vocabulary from the dictionary: query, key, value. It drops the dictionary's one strict rule. A hash map returns the value whose key equals the query, or nothing. Attention returns every value, weighted by a softmax over how well each key matches. Lower the softmax temperature and the weights pile onto the best match, which turns attention back into a lookup, for the nearest key instead of an identical one.

Try it · drag the query

    Drag q anywhere. As the temperature drops, attention gives nearly all its weight to the nearest key. The hash map only answers when q is released on a key exactly; release it close to one and it snaps there, the way you'd type the exact key.

    02

    Everyone wants the same bucket

    completed 7 May 2026

    collisions162 days

    A semantic ID is a hash that is supposed to collide, since similar items should share a prefix. When two items end up with the same full code, the RecSys notes reach for the fixes from the hash-table note. TIGER appends one more digit, which is separate chaining with the position in the chain written into the ID. LC-Rec reassigns the last level under a uniform constraint, which is what a better-spread hash function buys. The GRID note compares the two and finds TIGER's digit slightly ahead.

    The MoE note meets the same problem under another name. When too many tokens pick one expert, “that expert becomes a queue while other experts sit idle”, so each expert gets a fixed capacity, like a bucket with a size limit.

    Three ways out of one collision

    Separate chaining (hash table)

    bucket 3·1·4 → [A] → [B]
bucket 3·2·7 → [C]
bucket 3·1·5 → ∅

    A and B share a bucket. Lookup walks the chain and compares keys.

    TIGER: append a digit

    A → 3·1·4·0
B → 3·1·4·1
C → 3·2·7·0

    The extra token is B's position in the chain, written into the ID.

    LC-Rec: spread the last level

    A → 3·1·4
B → 3·1·5
C → 3·2·7

    Optimal transport pushes B into an empty last-level code: a better-spread hash.

    03

    Counting walks

    completed 18 May 2026

    powers of A56 days

    LightGCN has no weight matrices inside its layers. Layer k is the normalized adjacency matrix raised to the k-th power, applied to the starting embeddings. If those embeddings were one-hot, the score between a user and an item would be exactly a weighted count of the walks between them. A walk of length 3, user → item → user → item, reads as “someone who liked what you liked also liked this”. That is collaborative filtering, derived from the exam fact.

    The RecSys note came first, two months before the graph-theory chapter. The final-exam note adds the warning that matters here: ordinary multiplication, not Boolean, because the counts are the signal.

    Try it · pick a user and a walk length

    Bars are one row of Ak: how many walks of length k lead from the user to each item. Highlighted edges lie on at least one of those walks. Hover an item to see them. The normalization is LightGCN's D−½AD−½, which discounts well-connected nodes.

    04

    Pruned prefixes

    completed 1 Jun 2026

    prefix search185 days

    Generating a semantic ID token by token is a walk down a trie of every valid ID. At each step, constrained beam search runs the prefix search from the data-structures note and keeps a candidate only if its path exists. The GRID note then reports the twist: constrained and unconstrained beam search score about the same, and skipping the trie is faster and cheaper.

    One step of trie-constrained beam search

    Beam width 2, second decoding step. The model's favourite continuation of 3 is 9, but no item's ID starts with 3·9, so the prefix search fails and the branch is pruned. The beam keeps 3·1 and 3·2.

    05

    A learned multiplexer

    completed 12 Jul 2026

    select lines13 days

    A top-1 mixture-of-experts layer is a multiplexer whose select lines are computed from the input and trained by gradient descent. The difference is where the work happens. A hardware mux has all of its inputs computed and wired in, and passes one of them through. An MoE layer runs only the expert it selects, which is the point of the design. Top-2 routing, as in Mixtral, has no mux equivalent: it blends two experts by their gate weights.

    06

    Greedy merges

    completed 14 Jul 2026

    merge by frequency42 days

    Both are the same loop: count, merge one pair, repeat. They work from opposite ends of the frequency table. Huffman merges the two rarest symbols, so rare symbols sink deep into the tree and get long codes. BPE merges the most frequent adjacent pair, so common strings collapse into single tokens.

    Both are compression, too. BPE was published in 1994 as a data-compression algorithm and moved into machine translation about twenty years later. GPT-2 runs it on UTF-8 bytes, the encoding in your character-encoding note from December.

    07

    The order of addition

    completed 8 Sep 2026

    (a+b)+c ≠ a+(b+c)299 days

    std::reduce may regroup a sum because it assumes the operation is associative. Floating-point addition is not: every partial sum is rounded, to 24 significant bits in fp32 and 8 in bf16. An inference engine that splits a reduction differently at small batch sizes gets slightly different logits from the trainer, even with identical weights. PPO's ratio between the two should be exactly 1, and sometimes it isn't. The mismatch note calls the result “an incorrect form of importance sampling”.

    The std::reduce note and your first RL note were added in the same commit, on 13 Nov 2025. Ten months later they meet here, with the IEEE 754 layout from your computer-organization note two days after that.

    Try it · same numbers, different order

    Orderfp32 sumbits: sign · exponent · fractionoff by

    4,096 random products added three ways, rounding after every addition as fp32 hardware does. Bits are laid out as in the IEEE 754 note; highlighted bits differ from left-to-right. The last column is the error against the exact sum, in units of the last place.

    Same weights, two kernels

    logit rounds to a different bf16 valueidentical

    Running 64 tokens through both kernels…

    A toy 4-layer network with bf16 activations runs 64 tokens twice with the same weights: once with each dot product summed left to right, once split into 4 chunks, as a kernel picked for a different batch size would do. Rows are tokens, columns are logits. A row with many lit cells is a token where one rounding flip in an early layer spread into everything computed after it.

    08

    Bellman, twice

    completed 12 Sep 2026

    Richard Bellman22 days

    Same Bellman. Richard Bellman's principle of optimality, that an optimal path is made of optimal sub-paths, drives both notes. Edge relaxation is a Bellman backup with costs instead of rewards, min instead of max, and no discount. Bellman–Ford sweeps every edge n − 1 times; value iteration sweeps every state until nothing changes.

    The negative-cycle check has a counterpart too. A cycle with negative total cost has no shortest path, and a loop with positive total reward has no finite value when γ = 1. Discounting with γ < 1 is how RL keeps those values finite.

    Try it · sweep toward the goal G

    A sweep updates every cell once from the previous sweep's numbers, as one pass of Bellman–Ford relaxes every edge. Distances start at ∞ and values at −∞, so both spread outward from G in the same wavefront. With γ = 1 the two views show the same numbers up to sign; lower γ and far-away values shrink toward −1/(1 − γ).

    09

    Forward, then backward

    completed 12 Sep 2026

    two sweeps over a DAG282 days

    The critical-path method and backpropagation share a skeleton: one sweep over a DAG in topological order to compute values, then one sweep in reverse to send information back. Only the arithmetic changes. Earliest times use max and +, latest times use min and −, and backprop uses + and × on local derivatives.

    The match goes one step further. Lengthen an activity by a day and the project length L* grows by a day if the activity is on a critical path, and not at all otherwise. That is a derivative of 1 or 0, and the key activities are exactly the edges where it is 1.

    Try it · an activity-on-edge network

    Click a duration to change it. The gradient view answers one question per activity: if it took one more day, how much later would the project finish?

    10

    The same two lines

    completed 26 Sep 2026

    the 2×2 rotation167 days

    Your note of 26 September, written for a graphics class, holds the same two equations as the RoPE note from April. glRotate turns a vertex by θ. RoPE turns each pair of query and key coordinates by the token's position times a frequency θi.

    The property graphics relies on to chain transformations, that rotations compose, is what makes RoPE a relative encoding: $R_m^\top R_n = R_{n-m}$, so the attention score depends on $n - m$ alone. Your RoPE note describes the feature pairs as “people walking around circles at different speeds”. Here they are, each one moved with the two lines from the graphics note.

    Try it · move the query and the key

    query at position m key at position n outer ring θ = 1 rad per position, inner ring θ ≈ 0.02

    Every dot is placed with x′ = x cos θ − y sin θ, y′ = x sin θ + y cos θ. Query and key carry the same content here, so each pair contributes cos((n − m)θi). Press shift or play: every dot moves, the bars and the score do not. The frequencies use base 100 so the slow rings visibly turn; real models use 10,000.
